# Model catalog and availability

Talk and Chat use Hermes's installed providers, credential handling, tools, and session runtime. The optional **Talk & Chat** model assignment overrides the main model for future local-assistant requests. It can use any configured Hermes provider, including native and OAuth providers. Choosing **Follow main model** removes that override, so later main-model changes also apply to Talk and Chat. A saved teammate can pin its own provider and model; that profile choice overrides Talk & Chat while the teammate is selected. The fallback assignment is a single object in the Hermes configuration.

Main and backup changes use a bounded process lock and re-read the latest configuration inside the mutation. Concurrent windows can update different roles without losing each other's settings. A busy mutation returns a retryable message after two seconds; failed mutations do not overwrite configuration.

The model interface opens on the provider used by the selected role. Its assignment cards distinguish a saved main or backup choice, a pinned Talk & Chat override, and Talk & Chat following the main model. Connected providers are shown first; providers that need setup and discovery-only IDs can be inspected separately. Known obsolete or specialized service IDs are excluded from the ordinary choices. Current main, fallback, and Talk & Chat assignments remain visible even when a catalog is incomplete. The workspace header labels a selected teammate's pinned model or says that the teammate follows Talk & Chat; it does not substitute the main model when those scopes differ.

**Saved choice** or **Pinned** means an exact provider and model ID are saved for that scope. **Following main** means Talk & Chat has no separate override. **Available to choose** means the provider is connected and the ID can be selected. These assignment and catalog labels do not claim that a provider has accepted a model prompt. Access appears separately as **Not tested**, **Test passed**, **Test failed**, **Unavailable**, or **Access unknown**. A provider that needs setup remains **Access unknown** even when an older saved choice is preserved.

The browser distinguishes installed, cached, and freshly fetched provider catalogs. Refresh calls the selected provider's model-list endpoint through the installed Hermes discovery code and stores registered provider IDs through Hermes's cache writer. It does not send a model prompt. An ID missing from a refresh stays visible if it is already selected, with an explanation that aliases and private model IDs can be omitted from discovery.

The explicit **Test access** action sends one small prompt to the configured provider and exact ID, with a 64-token output limit and a 12-second network deadline. A valid generated response records **Test passed**; authentication, missing ID, rate limit, timeout, and invalid response errors are reported distinctly. A failed test does not remove or change a saved assignment, because account state and provider availability can change. No models are automatically tested on opening or refreshing the page. Native login/runtime providers without a supported direct API protocol are tested by a normal Hermes conversation instead.

Saving and testing are separate operations. A saved assignment applies to new requests in that scope; an in-flight request keeps the route it started with. If Panel receives a successful save response but cannot refresh local state, it reports that the choice was saved and asks for a reload. If the response is interrupted, Panel treats the result as uncertain and asks for a reload before retrying rather than claiming the old choice is unchanged. The picker uses one model-switch mutation and does not rewrite provider connection settings.

Tests follow Hermes's token-limit compatibility for OpenAI chat models. A reasoning model may spend the small budget before producing answer text; a structured successful response with explicit generated reasoning-token usage also proves access. An empty HTTP 200 alone does not.

Only the latest test metadata per provider and ID is saved locally in `data/model-probes.json`: status, time, latency, and an application-generated explanation. Provider response bodies, test output, endpoint URLs and keys are never saved there or returned to the browser. Evidence expires after 30 days and is invalidated when that provider's connection/account inputs change: keys, endpoints, private headers, account identities, credential-pool material or priorities, and referenced environment variables. Bookkeeping timestamps, request counts, display labels, other providers' credentials, selected model IDs, unrelated Hermes settings, build stamps, npm lifecycle values, local ports, and process metadata do not invalidate an otherwise unchanged connection. Fingerprints are computed from local state without refreshing credentials or sending model prompts; hashes and environment references remain server-only.

Completed run receipts may show a model route, but they do not create catalog test evidence. The receipt labels a route **Runtime reported** only when the connected runtime returns its selected provider or model after session initialization. Otherwise it labels the saved/requested route **Requested route**. Neither receipt replaces **Test access**, and historical runs do not establish current provider availability.

NVIDIA's discovery endpoint can contain specialized services alongside conversation models. The picker excludes identifiable embedding, moderation, reward, speech/translation, parser, detector, and calibration services. It also excludes hosted endpoints explicitly marked deprecated by NVIDIA; selected deprecated IDs remain visible with a warning and cannot be newly selected. The source URLs for those statuses are recorded in `scripts/models/hermes-catalog.py` and were reviewed on September 19, 2026. This is a partial list of known deprecations, not a claim that every remaining endpoint is operational. Deprecated shared-hosted status does not block the same model on a configured self-hosted endpoint.

The former fixed list of 15 IDs has been removed. Newly discovered models can appear without changing application code. Use an exact custom model ID for a provider when supported; a custom entry cannot bypass a known NVIDIA hosted deprecation.

Official sources include [NVIDIA hosted API considerations](https://docs.nvidia.com/aiq-blueprint/2.2.0/customization/swapping-models.html#nvidia-hosted-api-considerations), [the NVIDIA catalog overview](https://docs.api.nvidia.com/nim/docs/introduction), and individual catalog entries such as [DeepSeek V4 Flash](https://build.nvidia.com/deepseek-ai/deepseek-v4-flash?nim=self-hosted), [Llama 3.3 70B](https://build.nvidia.com/meta/llama-3_3-70b-instruct), and [Kimi K2 Thinking](https://build.nvidia.com/moonshotai/kimi-k2-thinking).
