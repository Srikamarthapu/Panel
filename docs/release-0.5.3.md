# Panel 0.5.3 release candidate

This candidate closes confirmed local-boundary and release-test gaps without changing Panel's single-user trust model. Page and React Server Component requests now require matching loopback request authority. API requests retain their origin, referrer, fetch-metadata, Tauri, and local-client rules. Custom-tab review text rejects concealed control, reordering, and Unicode tag characters at model parsing, saved-state interpolation, and server launch; ordinary multilingual text, joiners, emoji, and variation selectors remain supported.

Runtime state is now admitted and completed against one verified execution identity. Expired work requests stop their verified child process, terminal delegation updates use a durable request and acknowledgement path, and late cleanup cannot take ownership of a newer run. Public replies and provider errors are narrowed before they reach the browser; request-body and multipart limits are enforced before expensive parsing, short provider keys remain masked, and voice configuration can use an environment key without persisting it.

Voice teardown now rejects obsolete queued effects and late completion callbacks while preserving accepted work. Setup replay, skip, and failure paths remain recoverable; startup can continue after a failed legacy import; deleted work folders can be renamed; and shared polling backs off while preventing an older response from overwriting newer state. These are deterministic lifecycle and browser-fixture checks, not evidence of a real provider call, microphone, speaker, or Bluetooth path.

The default browser harness now creates a production build from its own temporary source stage and starts it on loopback. It excludes `.env` files, strips provider credentials, uses empty Hermes and Panel data roots, refuses to reuse an unknown server, and cleans up its owned files and process. `PANEL_TEST_URL` remains an explicit external-server opt-in. Portable Python adapter checks run under `npm test`; native-runtime skips are not passes. The installed-Hermes command fails before interpreter start until bootstrap and the installed product can be fully sandboxed.

Source exports are pinned to the reviewed paths, sizes, and SHA-256 hashes in `scripts/release/source-files.json`. The prepare command writes a candidate outside the checkout; review shows added, removed, and changed files; approval is explicit; verification and export fail if source drifts or a newly eligible file appears. The exported directory still requires the release scanner and ordinary test/build checks.

Development-only voice routes and unverified recorded-audio fixtures are excluded from the source bundle. The retained lifecycle fixture synthesizes audio for deterministic browser checks.

The final portable `npm test` gate passed 543 Node unit checks, 82 property checks, and 28 portable Python checks. Another 22 Python checks were explicitly skipped because they require the native Hermes runtime; those skips are not passes. The isolated production-build browser gate passed 136 Chromium checks and 36 selected WebKit onboarding and voice checks. The release build completed and 13 isolated production HTTP contracts passed without provider configuration. Run the exported-checkout gate before publication. Historical 0.5.2 results in `RELEASE-CHECKS.md` do not validate this candidate. No provider call, physical audio check, native notarization, or second-Mac clean install is implied by these changes.
