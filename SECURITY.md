# Security

Panel is a local, single-user application that can ask an installed Hermes runtime to execute tools with your permissions. Bind it to loopback, use your own credentials, and review Hermes's tool approval settings. It is not designed to be exposed through a public tunnel, reverse proxy, or shared server.

Do not put secrets, private transcripts, or an exploitable proof of concept in a public issue. If you discover an exposure, stop the local server and preserve a minimal redacted reproduction. Prefer GitHub's private vulnerability-reporting flow for this repository when it is available. If it is unavailable, open a public issue containing no sensitive detail and ask the maintainer for a private reporting channel. The project does not currently publish a separate security email address.

Never publish the development workspace wholesale. The release export copies only files and hashes in `scripts/release/source-files.json`; any source change or newly eligible file invalidates that reviewed manifest. Prepare a candidate outside the checkout, review its added/removed/changed paths, approve it explicitly, export to a new directory, and scan the export before publishing. Git history, local state, environment files, launch agents, recordings, and built apps are outside the manifest. A pattern scanner reduces accidental leakage but cannot prove the absence of all private data.
